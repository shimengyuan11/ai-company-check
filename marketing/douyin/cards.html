外贸业务的老毛病
不是不努力

  • 客户资料散在四个地方微信、WhatsApp、Excel、脑子里。换个人接手，前面聊到哪一步全断
  • 收到陌生公司线索先犯难查底细要 Google + LinkedIn + 海关数据翻一遍，20 到 30 分钟起
  • 该跟的人想不起来报价发了三天没回音，全靠自己记；想主动跟一句，又怕太生硬
这三件事都不难，难的是每天重复。重复的事情就该交给系统。

MERIDIAN03 / 09

① 输入公司名
出一份背调

公司概况 / 主营 / 规模 / 风险点 / 建议，五段式，300 字以内。

  • 宁说不知道，也不编提示词硬性禁止编造员工数、营收、注册资本；不确定的一律写「未验证：需人工核实」
  • 事实和推断分开写推断必须标明「推断」，让人知道哪句能拿去谈判
  • 历史按人隔离别人看不到你查过哪些公司
AI 在这里的角色是 省掉 20 分钟初筛，不是替你下结论。
模型可自己接：OpenAI 兼容任意网关不内置 key
MERIDIAN04 / 09

② 客户和跟进
一处管完

  • 建档只填 3 个字段姓名 / 号码 / 国家，回车就存；写跟进只有 1 个输入框
  • 阶段六档 + 未联系天数3 / 5 / 7 / 10 天没联系，一筛就出来该跟谁
  • 各管各的，但能移交普通业务员只看自己名下；人走了把客户转给接手的，对方打开就知道聊到哪
  • 防撞单同一个号被同事建过，建档直接被拦——但不会告诉你对方是谁
权限过滤写在 SQL 里没有「忘了过滤」的函数
MERIDIAN05 / 09

③ 话术库 +
AI 草稿

模板团队共享，标签能停用、能删、能合并。

  • 生成时会喂最近 3 条跟进「聊到哪一步」才是写话术最要紧的上下文，只给客户资料的话，写出来跟谁都能套
  • 界面回显依据「依据：客户资料 + 3 条跟进 + 模板 X」，AI 就不是黑箱
  • 只出草稿，不代发禁止编造价格 / 数量 / 交期，缺的写成问题去问对方
有限额：每人每天次数上限 + 按月 token 额度，到顶就拦住，不让成本悄悄失控。
生成记录跟客户权限走看不到客户也看不到记录
MERIDIAN06 / 09

④ 一个实例
装下多家公司

邀请码就是组织。第一家公司的管理员，也看不到第二家的客户。

  • 跨组织一律当它不存在不是提示「无权访问」，是返回 404——连「存在」都不泄露
  • 组织内部规则不变本组织管理员仍能看到同事的客户，离职转接照旧
  • 移交下拉也不越界不会把别公司的同事列出来
为什么加这层：没人愿意把客户名单放进一个「平台方能随时看」的系统。
默认单组织，单团队用完全无感4 项隔离测试

给同行看的
工程细节

  • 77 项回归测试，跑在临时 schema 上每次建一个一次性 schema，跑完 drop——不碰生产数据
  • 权限写进 SQL，不写在前端前端藏按钮不算数；每个接口自己验身份，服务端 302 挡未登录
  • 性能是量出来的gzip：63.8KB → 16.6KB；客户详情 4 个串行请求改并行，总耗时≈最慢那个
  • 密钥加密存、永不回传模型 key 存数据库、加密、接口只返回名字和模型名
FastAPIPostgres原生 JSthree.jsRender
没有 ORM，手写 SQL 更透明时间统一存 UTC

它还很粗糙
缺口我列出来

  • WhatsApp 直接接入方案已写进 docs：用官方 Cloud API，不用逆向库；卡在 24 小时窗口与模板审核
  • 模板 / 产品 / 选项还没按组织隔离多家公司共用一个实例时，这些「团队词典」会互相看到
  • 没有移动端，没有 CI窄屏只是隐藏了装饰元素；测试靠手动跑，还没接流水线
  • 开通第二个组织要手工插一行 SQL没有平台方管理界面
